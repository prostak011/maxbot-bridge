# MaxBot Bridge

Userbot мессенджера **MAX** (библиотека [pymax](https://github.com/MaxApiTeam/PyMax)) в виде
Home Assistant-аддона. Слушает **все чаты**, распознаёт названия чатов и имена участников
(с режимом обучения), передаёт текст и фото в вебхук (OpenClaw / n8n), принимает ответы
через локальный HTTP API.

## Установка

1. Add-on Store → три точки → «Репозитории» → добавить
   `https://github.com/ВАШ_ЛОГИН/maxbot-bridge`.
2. Установите **MaxBot Bridge** из раздела «Локальные».
3. Заполните опции:
   - `max_phone` — ваш номер в MAX (+7XXXXXXXXXX); нужен для SMS-входа
   - `auth_method` — способ первого входа: `qr` (по умолчанию) или `sms`
   - `webhook_url` — куда слать конверты (вебхук OpenClaw/n8n);
   - `webhook_token` — общий секрет (заголовок `X-MaxBot-Token`);
   - `approval_chat_id` — чат утверждения (вопросы «кто это?» и ответы).
4. Запустите аддон. Откройте **`http://homeassistant.local:8099/auth`**:
   - **Вход по QR** (рекомендуется): приложение MAX → Настройки → Устройства →
     сканировать QR. Без SMS и лимитов.
   - **Вход по SMS**: кнопка «Запросить SMS-код», затем введите код из SMS.
     Внимание: MAX ограничивает частоту запросов кода — при переподаче
     подождите 5–10 минут.
   Выбранный способ сохраняется в `/data`. Сессия — `/data/cache/main.db`,
   переживает перезапуски; при обновлении аддона повторный вход не нужен.

## Режим обучения именам

Если бот встречает незнакомого участника или чат без названия, он спрашивает
в чате утверждения:

```
❓ Неизвестный участник ID 236545478 (сообщение в чате 354 цех).
Ответьте: ID 236545478 = Александр
```

Ответ `ID 236545478 = Александр` (или `ЧАТ -72605995617734 = 354 цех`)
сохраняется в `/data/people.json` / `/data/chats.json` и используется навсегда.
Тот же эффект через API: `POST /learn {"type":"person","id":123,"name":"Иван"}`.

## HTTP API (порт 8099)

| Метод | Путь | Описание |
|---|---|---|
| GET | `/health` | статус, для watchdog |
| GET | `/auth` | страница входа (QR + SMS, табы) |
| GET | `/auth/status` | mode, connected, need_code, qr_url |
| GET | `/auth/qr.svg` | QR-картинка (SVG) |
| POST | `/auth/code` | `{"code": "1234"}` — SMS-режим |
| POST | `/auth/method` | `{"method": "qr"\|"sms"}` — переключить на лету |
| POST | `/auth/request_code` | запросить новый SMS-код |
| GET | `/chats` | список чатов с названиями |
| GET | `/names` | выгрузка people/chats |
| POST | `/send` | `{"chat_id", "text"}` — отправка в MAX (токен) |
| POST | `/learn` | обучение именем (токен) |

Защищённые `/send` и `/learn` требуют заголовок `X-MaxBot-Token` = `webhook_token`.

## Формат конверта (POST на webhook_url)

```json
{
  "type": "message",
  "source": "max",
  "chat_id": -72605995617734,
  "chat_name": "354 цех",
  "chat_unknown": false,
  "message_id": 123,
  "from_id": 236545478,
  "from_name": "Александр",
  "from_unknown": false,
  "text": "текст сообщения",
  "files": [{"type": "photo", "photo_id": 1, "base64": "..."}],
  "timestamp": "2026-09-06T12:00:00+00:00"
}
```

Если в ответе вернуть `{"answer": "текст"}` и включить опцию `auto_reply`,
мост отправит текст обратно в чат. По умолчанию ответы приходят через
`POST /send` из автоматизации OpenClaw.

Сообщения из чата утверждения (кроме команд обучения) уходят в вебхук с
`"type": "approval"` — так OpenClaw получает управляющие команды.

## LISTEN-ONLY режим (v0.5.0, 26.09.2026)

Три уровня обработки входящих — экономит вызовы модели:

| Уровень | Что происходит | Стоимость |
|---|---|---|
| **ignore_chats** | конверт выбрасывается, ничего не пишется | 0 |
| **listen_chats / listen_people / listen_unknown** | конверт пишется в JSONL-контекст, вебхук **не вызывается** | 0 |
| обычный | конверт → вебхук → агент → черновик на утверждении | вызов модели |

Опции:
- `ignore_chats` — ID чатов, которые не обрабатывать вообще.
- `listen_chats` — ID чатов: не отвечать, но копить контекст.
- `listen_people` — **ID пользователей** (фильтр по отправителю!). Нужен для личных чатов инженеров/склада: работает сразу, даже если личный чат ещё не создан.
- `listen_unknown` — чаты без названия по умолчанию только слушаются (иначе каждый новый безымянный чат дёргает модель).
- `history_dir` — куда пишется контекст (по умолчанию `/share/kb/history/maxbot`).

Чтение накопленного контекста:

```bash
GET /context?days=1&limit=200      # без токена
```

Агент читает эти файлы напрямую (`read` tool) — они лежат в `/share`, общий том с OpenClaw.

### `answer_chats` (v0.5.1) — приоритет над listen-фильтрами

Рабочие чаты (354/355/655) отвечают **всегда**, даже если отправитель входит
в `listen_people`. Без этого прямой вопрос инженера/склада в своём цехе
уходил бы в молчание. Порядок проверок в `listen_reason`:

1. `answer_chats` → вебхук (всегда)
2. `listen_chats` → в контекст
3. `listen_people` (по отправителю) → в контекст
4. безымянный чат → в контекст
5. иначе → вебхук

### v0.5.2 — «Кто это?» больше не спрашивается у listen-чатов
`listen_reason()` проверяется **до** режима обучения именам. Чат без названия в
listen/ignore-режиме больше не порождает вопрос «❓ Неизвестный чат» в «Отработке».
Вопрос задаётся только для чатов, которые реально пойдут в вебхук.

### v0.5.3 — vision не тратится на listen-чатах

Фото в чатах, куда секретарь не отвечает, **не анализируются** vision-моделью.
Цена вопроса: ~12 с на фото, сообщение из 9 фото = ~1,5 минуты GPU впустую.
Путь фото всё равно пишется в контекст (`files[].share_path`).

Опция `vision_in_listen: true` возвращает прежнее поведение, если распознавание
фото из 372/закупочных чатов нужно для контекста.
